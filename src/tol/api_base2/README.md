# Tree of Life API Base v2

This is the second version of an automatic API generator from data models.

## Architecture

This library follows the [Model-View-Controller](https://en.wikipedia.org/wiki/Model-view-controller) design pattern.  Learning from the previous attempt, a great deal of effort has been made to use [Dependency Injection](https://en.wikipedia.org/wiki/Dependency_injection) throughout.

## Model

The unifying **model** concept is `DataSource` instances _operating_ on `DataObject` instances. There are (right now) three such _operations_, each of which must either be implemented, or decorated with `@unsupported`:

1. `get_by_id` - for a string object_type, and an `Iterable` of string id's, it returns a list of either `None` or the found `DataObject` instance for the id at that position.
2. `get_list_page` - for a string object_type and integer page number, alongisde various keyword arguments (such as page_size, and directives for sorting and filtering), it returns a list "page" of `DataObject` results.
3. `get_list` - functions much like `get_list_page`, except there are no pages - it returns a `Generator` of `DataObject` results.

Many `DataSource` instances can co-exist on the same API. Each `DataSource` implements the `@property` `supported_types` - this documents what string types of `DataObject` it supports, and can either be _statically_ defined (for simple cases) or _dynamically calculated_.

## View

For now, API's generated by this package only support **Read-Only** access. To this end, views that inherit from the `View` abstract base class provide (just) serialization of either a single `DataObject` instance, or an `Iterable` thereof, to [JSON:API v1 format](https://jsonapi.org) using the `dump()` and `dump_bulk()` methods respectively. 

## Controller

A new instance of `Controller` is created for every API request. Its constructor arguments are:

1. A `DataSource` instance (supporting the specified type of `DataObject`)
2. A `View` instance
